    Escenarios de examples/¶

    Cada escenario es un sdaf.config.yaml de referencia a copiar en la raíz del consumidor y ajustar (project.name, stack.src_path, stack.tests_path).

    01-pack-only.yaml — playbooks sin activar agentes de extensión¶

    # Pack de stack sin cambiar el modelo de agentes del core.
# Copia a la raíz del consumidor y ajusta project.name.
# Requiere sdaf-core@0.2.x y materializar skills/playbooks de este pack.

sdaf:
  version: "0.2.0"

project:
  name: MiProyecto
  language: es

stack:
  pack: sdaf-stack-dotnet@0.1.1
  src_path: src
  tests_path: tests

agents:
  active:
    - specification
    - architecture
    - testing-review
  stubs:
    - product
    - domain
    - application
    - devops
    - review
    - testing
    - frontend
    - domain-application
    - infrastructure
  fusions: {}

    Uso: adoptar solo playbooks/skills del pack manteniendo el modelo de agentes por defecto de sdaf-core (specification, architecture, testing-review activos; el resto en stub).

    02-pack-frontend.yaml — activa domain-application + frontend¶

    # Pack + domain-application + frontend (extensiones del pack).
# Handoff: Specification → Architecture → domain-application → frontend
#                                                    ↘ testing-review ↗

sdaf:
  version: "0.2.0"

project:
  name: MiProyecto
  language: es

stack:
  pack: sdaf-stack-dotnet@0.1.1
  src_path: src
  tests_path: tests

agents:
  active:
    - specification
    - architecture
    - domain-application
    - frontend
    - testing-review
  stubs:
    - product
    - domain
    - application
    - infrastructure
    - devops
    - review
    - testing
    - ai
  fusions:
    testing-review: [testing, review]
    domain-application: [domain, application]

    Uso: handoff completo Specification → Architecture → domain-application → frontend ↘ testing-review ↗. Activa la fusión documentada en ADR-0001.
