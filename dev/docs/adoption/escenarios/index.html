    01-pack-only.yaml: playbooks sin activar agentes de extensión¶

    # Pack de stack sin cambiar el modelo de agentes del core.
# Copia a la raíz del consumidor y ajusta project.name.
# Requiere sdaf-core@0.4.x (pin árbol v0.4.2) y materializar skills/playbooks de este pack.
# Parte de sdaf-core examples/04-pack-stack.yaml; además lista los ids de
# extensión del pack como stubs para dejar explícito que no se activan.
# CI: validado con la action validate-sdaf del core (--strict-i4).

sdaf:
  version: "0.4.0"

project:
  name: MiProyecto
  language: es

stack:
  pack: sdaf-stack-dotnet@0.3.0
  src_path: src
  tests_path: tests

agents:
  active:
    - specification
    - architecture
    - testing-review
  stubs:
    - product
    - domain
    - application
    - devops
    - review
    - testing
    - frontend
    - domain-application
    - infrastructure
    - ai
  fusions: {}

    Uso: adoptar solo playbooks/skills del pack manteniendo el modelo de agentes por defecto de sdaf-core (specification, architecture, testing-review activos; el resto en stub).

    02-pack-frontend.yaml: activa domain-application y frontend¶

    # Pack + domain-application + frontend (extensiones del pack).
# Handoff: Specification → Architecture → domain-application → frontend
#                                                    ↘ testing-review ↗
# Alineado con sdaf-core examples/07-pack-frontend.yaml.
# Requiere sdaf-core@0.4.x (pin árbol v0.4.2).
# domain y application quedan en stubs: sus miembros se activan solo a través
# de la fusión domain-application (ADR-001 del pack), nunca por separado.
# CI: validado con la action validate-sdaf del core (--strict-i4).

sdaf:
  version: "0.4.0"

project:
  name: MiProyecto
  language: es

stack:
  pack: sdaf-stack-dotnet@0.3.0
  src_path: src
  tests_path: tests

agents:
  active:
    - specification
    - architecture
    - domain-application
    - frontend
    - testing-review
  stubs:
    - product
    - domain
    - application
    - infrastructure
    - devops
    - review
    - testing
    - ai
  fusions:
    testing-review: [testing, review]
    domain-application: [domain, application]

    Uso: handoff completo Specification → Architecture → domain-application → frontend ↘ testing-review ↗. Activa la fusión documentada en ADR-001.

    domain y application aparecen en stubs y a la vez como miembros de la fusión: no se activan por separado, solo a través de domain-application. Tenerlos en agents.active junto con la fusión incumple el contrato.

    Validación¶

    Los dos escenarios se validan en el CI del pack con la composite action validate-sdaf de sdaf-core v0.4.2 (schema + invariantes, I4 en modo estricto). En local, con un checkout del core al lado:

    python ../sdaf-core/scripts/validate-config.py --strict-i4 --consumer-root . examples/01-pack-only.yaml examples/02-pack-frontend.yaml
